# 화물 재배치 기준

2026-10-31 초안이다. 사용자가 확정한 항목과 남은 항목은 [결정 기록](#결정-기록)에 있다.
결정은 [ADR0017](../adr/0017-rule-governed-rearrangement-decision.md)에 기록했다. 규칙·계산·결정 모델의 판단 구조와 협의 절차는 ADR0017이 정본이다. 이 문서는 지표·인자·시험의 상세를 정한다.
R0·R1은 여전히 현재 구현([ADR0010](../adr/0010-automatic-placement-and-replanning.md),
[설계22](22-automatic-placement.md), [설계26](26-linked-yard-and-ranked-recommendation.md))이 정본이다. 순서 판정은 R0·R1·R2가 `order_relation` 하나를 쓴다. R1 점수는 `restoration_lex_v3`로 미확인 항을 막힘 바로 다음에 둔다. 이미 저장된 v1·v2 계획은 자기 표시 항목으로 계속 읽힌다. R1도 `rotation_moves`(설치된 회전 쌍)에 있는 구역 쌍에서 2·3칸 화물의 0↔90° 회전 후보를 연다. 반출 이동(야드→반출대)도 포함한다. 복귀 회전 수는 구역 변경 바로 다음 항이다. 지금은 설치된 회전 쌍이 없어 업무 경로는 빈 집합을 넘기므로 동작이 같다(Q8 실물 확인 뒤 설계29에 넣는다).

**구현 상태(2026-10-31):**
- R2 계산 `plan_rearrangement`와 판정 함수 `order_relation`은 `harbor/spatial.py`에 있다. 시험은 `tests/test_rearrangement.py`다.
  - 탐색: 폭 8의 beam 탐색이다. 상태 한도는 R1과 같다.
  - 회전: 설치 대응은 `(출발 구역, 도착 구역)` 쌍 집합으로 받는다. 설계29에 회전 항목이 생기면 그 값을 넘긴다.
  - 대기 입고는 길이 목록으로 받는다. 한 길이에 자리가 하나라도 있으면 막힘이 아니다. 입고끼리 같은 자리를 다투는 경우는 세지 않는다.
- 실행 계층(`harbor_web/rearrangement.py`, 화면 `/rearrangement/`)이 있다.
  - 허용 범위는 `RearrangeAuthorization`에 쌓는다. 값을 바꾸면 새 행이 되고 이전 행은 꺼진다. 켜고 끄는 권한은 실행 확정과 같은 operator 역할이다.
  - `REARRANGE` 지시는 화물 없이 저장한다. 반출 대기열 digest에는 넣지 않는다. 사용자 직접 요청(`requested=True`)은 계획만 만들고 기존 사용자 확정을 따른다.
  - 업무 실행기가 유휴일 때 한 번 검사한다. 조건을 어기면 Command 없이 HOLD 이유를 감사 기록에 한 번 남긴다. 반출 순서 변경·새 관측은 별도 hook 없이 다음 유휴 검사가 받는다.
  - Plan에 허용 ID, 실행 전후 B·N, 개선량, 이동 수를 남긴다.
  - 반출 지시가 생기면 단계 사이(`PLANNED`, 두 번째 이동부터)에서 다음 이동을 시작하지 않는다.
- 아직 없는 것:
  - 결정 모델 협의(Q10).
  - 다칸 이동 Command의 칸 단위 설치 대응(설계29).
    - **임시 처리(2026-10-31):** 설치 파일에 `simulation_cell_template`(workcell, 팔별 instance)이 하나 있으면 각 이동을 앵커 주소 사이 ARM 이송으로 바꾼다(`harbor/process.py::SimulationCellTemplate`).
    - 기존 simulation 관문 안에서만 열린다. 조건은 test·development 모드, `HARBOR_WEB_ALLOW_SIMULATION=1`, loopback Fleet, SYNTHETIC 관측이다.
    - ledger는 한 화물의 최종 위치로 완료를 판정한다. 그래서 정확히 한 번 움직이는 화물의 도착지를 완료 위치로 쓴다. 그런 화물이 없는 계획은 계속 `SPATIAL_EXECUTION_BINDINGS_REQUIRED`다.
    - 실물 실행 전에는 설계29의 이동별 칸 대응으로 바꿔야 한다. 그 전까지 실물 관측(DECLARED·AUTHENTICATED)에서는 Command가 만들어지지 않는다.
  - 반출 때문에 멈춘 R2 Command를 닫는 자동 절차. 사람이 취소·종료해야 한다.
  - 회전 대응(`rotation_moves`)과 입고 예약 칸(`reserved`)은 계산에 넘기지 않는다. 대기 입고 길이는 최신 Plan이 `NO_LEGAL_PLACEMENT`인 입고 지시에서 읽는다.
- 실물 수용은 하지 않았다.

## 왜 기준이 필요한가

반출 순서에 따라 화물 위치를 고르는 계산은 지금 두 곳에 있다. 입고 위치를 고르는 `plan_placement`와 반출 뒤 재취급 화물의 복귀 위치를 고르는 `plan_spatial`이다.
두 곳은 순서를 판정하는 규칙이 서로 다르다. 그리고 이미 쌓인 야드를 순서에 맞게 다시 쌓는 업무는 없다.
재배치를 늘리기 전에 다음 세 가지를 한 곳에서 정해야 한다.

- 무엇을 재배치라고 부르는가.
- 재배치를 어느 구조에 두는가.
- 각 입력(인자)에 어떤 기준을 적용하는가.

## 재배치의 종류

| 구분 | 언제 | 움직이는 화물 | 현재 |
|---|---|---|---|
| R0 입고 위치 선택 | 입고 지시 | 들어오는 화물 1개 | 있음. `plan_placement` |
| R1 복귀 위치 재선택 | 반출 중 | 이번 반출의 재취급 화물 | 있음. `plan_spatial` 복귀 단계는 원위치에 묶이지 않는다 |
| R2 독립 재배치 (사전 정리) | 반출 지시 없이 | 순서가 어긋난 야드 화물 | 없음 |
| R3 반출 중 범위 확장 | 반출 중 | 재취급 화물이 아닌 화물까지 | 없음 |

**결정:** R0·R1은 유지하고 판정 규칙을 통일한다. R2는 사용자가 설정한 허용 범위 안에서 자동으로 실행한다([자동 실행](#r2-자동-실행)). R3도 필요할 때 연다.

**허용 원칙(2026-10-31 사용자 지시):** 회전·이동 종류·범위 확장은 점수를 낮추는 데 필요하면 허용한다. 막는 이유는 물리 불가와 안전 두 가지뿐이다. 둘 다 Harbor가 직접 판단하지 않고, 설치 기준과 ROSY 검증에서 받는다.

**R3 허용 조건:** 반출 계획 안에서 재취급 화물이 아닌 화물을 함께 옮기는 것은 다음을 모두 만족할 때만 허용한다.

- 추가 이동이 R2와 같은 실행 조건을 만족한다.
- 다른 반출 지시가 대기 중이 아니다. 반출 대상 화물이 반출대에 나가는 시점을 늦추지 않도록, 추가 이동은 반출 뒤 복귀 단계에만 넣는다.
- 업무 완료 조건에 `rearranged_at_targets`를 더한다. 완료 조건은 반출 대상 화물이 반출대에 있음, 재취급·재배치 화물이 목표 위치에 있음, 관련 팔 퇴피다.

추가 이동의 단계 이름은 `재배치`로, `복귀`와 구분한다.

## 공통 기준: 순서 판정

반출 순서는 반출 지시(`Order.kind='OUTBOUND'`)의 `(priority_group, sequence)`다. `tie_policy`가 `FIXED`가 아니면 sequence는 없음(None)으로 본다. 입고 지시 순서는 반출 순서로 쓰지 않는다(ADR0010).

아래 화물 L 위에 위 화물 U가 지지 체인으로 얹혀 있을 때 판정은 다음과 같다.

| L의 순서 | U의 순서 | R0 (`plan_placement`) | R1 (`plan_spatial`, `leaves_earlier`) | 제안 |
|---|---|---|---|---|
| 있음, 그룹이 앞 | 있음 | 막힘 | 막힘 | 막힘 |
| 같은 그룹, 둘 다 sequence, L이 앞 | | 막힘 | 막힘 | 막힘 |
| 같은 그룹, sequence 하나 이상 없음 | | **미확인**(2순위 점수) | **무관**(0점) | 무관 (Q4 결정: 같은 그룹 안 순서 자유를 지시한 것) |
| 있음 | 없음 | 막힘 | 막힘 | 막힘 (U는 가장 늦게 나간다고 본다) |
| 없음 | 아무거나 | **미확인**(2순위 점수) | **무관**(0점) | 미확인으로 통일 |

- 막힘: 나중에 L을 반출하려면 U를 재취급해야 한다.
- 미확인: 순서를 몰라 막힐 수도 있다. 막힘 다음 순위로 피한다.

**제안:** 판정 함수를 `harbor/spatial.py`의 한 함수로 합쳐서 R0·R1·R2가 함께 쓴다. 이 함수는 (막힘, 미확인)을 돌려준다. R1 점수에도 미확인 항을 막힘 바로 다음에 넣는다. 그러면 objective version이 바뀐다(`restoration_lex_v3`).

## 공통 지표: 예상 재취급 수

야드 전체가 얼마나 순서에 맞게 쌓였는지는 지표 하나로 잰다.

- **막힘 쌍 수 B:** 지지 체인에서 위 화물 U가 아래 화물 L보다 늦게 나가는 (U, L) 쌍의 수. 지금 R1 점수의 첫 항(`earlier_outbound_buried`)을 야드 전체로 넓힌 값이다.
- **미확인 쌍 수 N:** 위 판정에서 미확인인 쌍의 수.

R0·R1이 고르는 위치는 B, N 증가를 최소로 하는 위치다. R2가 고르는 목표 배치는 아래 지표 전체의 개선을 이동 비용과 맞바꾼 결과다.

## 회전으로 얻는 것

회전은 비용이 아니라 목적이 될 수 있다(2026-10-31 사용자 지시). 돌아가 있는 화물을 바로 놓거나 다른 화물을 돌려서 얻는 것이 크면 회전한다. 회전으로 얻는 것은 다음 지표로 잰다.

| 지표 | 정의 | 회전으로 좋아지는 예 |
|---|---|---|
| U 반출 불가 화물 수 | 지금 방향으로는 반출대에 놓을 수 없는 화물 수 | 반출대는 1행×3열이다. 90°로 놓인 2·3칸 화물은 반출대에 들어가지 못한다. 현재 반출 계획은 원래 방향을 유지하므로 이 화물은 HOLD된다 |
| B 막힘 쌍 수 | 위 정의 | 돌리면 먼저 나갈 화물 위를 덮지 않는 칸에 들어간다 |
| X 교차 지지 수 | 서로 다른 둘 이상의 화물에 걸쳐 놓인 화물 수 | 열을 가로질러 걸친 긴 화물을 한 줄 위로 돌려 놓으면 지지 체인이 짧아진다 |
| N 미확인 쌍 수 | 위 정의 | B와 같다 |
| F 수용 가능 위치 수 | 1·2·3칸 화물 각각을 새로 놓을 수 있는 합법 위치 수의 최솟값 | 흩어진 빈 칸을 한 줄로 모아 3칸 화물이 들어갈 자리를 만든다 |

**반출할 때 바로 돌리기:** R1 반출 이동(야드→반출대)에도 회전 후보를 연다. 반출대 방향에 맞게 돌려 놓는 것이 설치돼 있으면 U가 반출을 막지 않는다.

**미리 돌리기:** 반출할 때 돌리는 것이 설치돼 있지 않은 칸이 있다. 이때는 R2가 유휴 시간에 그 화물을 회전이 가능한 위치·방향으로 옮겨 둔다.

**입고 막힘 풀기:** 대기 중인 입고가 `NO_LEGAL_PLACEMENT`인데 회전이나 재배치로 자리가 생기면 R2를 검사한다.

## 구조

```
자동 재배치 허용(사용자 설정) ─▶ 업무 실행기가 조건 검사
        ─▶ plan_rearrangement ─▶ Plan(plan_kind='rearrangement')
             (harbor/spatial.py)          │
             - 순서 판정·B/N 공유           ▼
             - plan_spatial 탐색 재사용     허용 범위 확인 ─▶ Command ─▶ 업무 실행기 ─▶ ROSY
```

- **도메인:** R2는 `harbor/spatial.py`의 새 함수 `plan_rearrangement(snapshot, policy, schedule, *, now, max_moves)`로 둔다.
  - `plan_spatial`의 상태 탐색, 지지·도달 검사, 탐색 한도, 결과 형식(`SpatialProposal`, `SpatialMove`)을 그대로 쓴다.
  - 단계 이름은 `재배치`다. 완료 조건은 `rearranged_at_targets`, `arms_retreated`이다.
  - 새 모듈이나 새 결과 형식은 만들지 않는다.
- **업무:** R2 Plan은 지시 종류 `REARRANGE`로 저장한다. 업무 실행기가 만들 때도, 사용자가 직접 요청할 때도 같은 종류다.
  - Plan 뒤의 Command → 업무 실행기 경로(ADR0013)는 반출과 같다.
  - Harbor가 목표 배치와 순서를 소유하고, ROSY는 도메인 중립 이동만 받는다. ROSY에 재배치 전용 endpoint를 만들지 않는다(ADR0013).
- **우선순위:** 반출 지시가 진행 중이거나 대기 중이면 R2는 `HOLD(OUTBOUND_PENDING)`이다. 반출이 언제나 먼저다. R2가 실행 중일 때 반출 지시가 들어오면 R2의 남은 이동은 새로 시작하지 않는다. 진행 중인 이동은 끝까지 마치고 관측으로 확인한다.

### R2 자동 실행

ADR0012는 "자동 계획 생성은 사용자 실행 확정을 대신하지 않는다"고 정했다. R2 자동 실행은 이 원칙을 다음 방식으로 지킨다. 사용자가 확정하는 대상이 각 계획이 아니라 **허용 범위**다. 이 예외는 [ADR0017](../adr/0017-rule-governed-rearrangement-decision.md) 결정 4에 기록했다. 결정 모델의 `veto`도 자동 실행 조건에 들어간다.

- **허용 범위:** 실행 권한이 있는 사용자가 한 번 켠다. 다음 값을 저장한다.
  - k와 `max_moves`
  - 유효 기간
  - 하루 최대 실행 횟수
  - 켠 사용자
  
  켜고 끈 이력은 지우지 않는다. 범위를 바꾸면 새 허용으로 저장한다.
- **자동 실행 조건:** 다음을 모두 만족할 때만 업무 실행기가 Command를 만든다. 하나라도 어기면 HOLD 이유를 남기고 실행하지 않는다.
  - 허용이 켜져 있고 유효 기간 안이다.
  - 반출 지시가 진행 중이거나 대기 중이 아니다.
  - 다른 Command가 진행 중이거나 결과 불명 상태가 아니다.
  - 관측이 신선하고, 계산에 쓴 revision이 실행 직전 revision과 같다.
  - holding(팔이 화물을 든 상태)이 없다.
  - 아래 실행 조건을 만족한다.
- **계획마다 남기는 기록:** Plan은 다음을 남긴다.
  - 허용 ID
  - 실행 전후 B·N
  - 이동 수
  
  사용자는 화면에서 자동 실행된 R2를 다른 업무와 구분해 보고, 허용을 끌 수 있다. 허용을 끄면 새 R2를 시작하지 않는다. 진행 중인 이동은 위 반출 우선 규칙처럼 마친다.
- **ROSY 쪽 선행 조건:** ROSY D-938이 팔 이송(`ARM_TRANSFER`)을 Fleet 정책 승인 범위에 열었다(2026-10-31 플랫폼 로컬 main 착지, 원격 게시 전). 자동 실행에는 Fleet 쪽에 다음이 필요하다. 하나라도 없으면 Harbor가 Command를 만들어도 Fleet 승인에서 멈추고, 이 상태를 자동 실행 완료로 보고하지 않는다.
  - 승인 범위에 Harbor 서비스 principal(`proposers`), 참여 팔, 상한, 만료 시각이 있다.
  - 기명 운영자가 실행 중에 그 범위를 켰다.
  - 지금은 simulation 팔 이송에서만 동작한다.

## R2 목표 함수와 실행 조건

후보 계획을 다음 순서로 비교한다(사전식).

1. 실행 뒤 반출 불가 화물 수 U
2. 대기 중인 입고 중 자리가 없는 수
3. 실행 뒤 막힘 쌍 수 B
4. 실행 뒤 미확인 쌍 수 N
5. 실행 뒤 교차 지지 수 X
6. 실행 뒤 수용 가능 위치 수 F (클수록 좋다)
7. 이동 수
8. 회전 수
9. 위치가 바뀐 화물 수
10. 층 합계

회전 수는 회전 자체를 막는 항이 아니다. 효과가 같은 계획 중에서만 덜 돌리는 쪽을 고른다. R1의 복귀 점수에도 회전 수를 "위치가 바뀐 화물 수" 앞에 넣는다.

**개선량 G:** 다음 값의 합이다.

- 3 × (U 감소)
- 3 × (자리가 생긴 입고 수)
- (B 감소)
- (X 감소)

U와 입고 막힘은 업무를 멈추게 하므로 막힘 쌍보다 무겁게 센다. 막힘 쌍 하나는 나중에 재취급 2회를 부른다. 업무가 멈추면 그보다 비싸다고 본다.

**실행 조건:** 다음 세 조건을 모두 만족할 때만 READY다. 하나라도 어기면 `HOLD(REARRANGE_NOT_WORTH)`이다.

- G ≥ 1
- 이동 수 ≤ `max_moves`
- (이동 수) ≤ k × G

G가 0이어도 F를 늘리는 계획은 사용자가 직접 요청할 때만 READY다. 자동 실행 대상은 아니다.

기본값은 k=2, `max_moves`=6이다(Q2 결정). 허용 범위에서 사용자가 이 값을 바꿀 수 있다.

## 수용 시험

다음 경우를 단위 시험으로 둔다.

- 순서가 같으면 R2는 이동 0, `HOLD(REARRANGE_NOT_WORTH)`.
- 반출 순서를 뒤집으면 B가 줄어드는 계획이 나온다.
- 이동을 재생하면 매 단계 지지·겹침이 유효하다(기존 `replay` 재사용).
- 임시 칸을 넘는 동시 재취급은 HOLD.
- yard→yard가 없는 정책에서는 모든 이동이 temp를 거친다.
- 반출 지시가 대기 중이면 `HOLD(OUTBOUND_PENDING)`.
- 자동 실행 조건을 하나씩 어긴 경우마다 Command 0건과 HOLD 이유가 남는다. 어긴 조건은 허용 꺼짐·만료, 다른 Command 진행, revision 변경, holding이다.
- 허용을 끈 뒤 새 R2가 시작되지 않는다.
- yard→yard가 있는 정책에서 같은 목표를 temp 경유보다 적은 이동으로 낸다.
- 회전해야만 들어가는 배치에서 회전 대응이 설치돼 있으면 READY, 없으면 `ROTATION_NOT_INSTALLED`로 HOLD.
- 회전 여부만 다르고 점수가 같으면 회전하지 않는 계획을 고른다.
- 90°로 놓인 2칸 화물의 반출은 다음과 같다.
  - 반출대 회전 대응이 있으면 회전해서 반출대에 놓는다.
  - 대응이 없으면 반출은 HOLD하고, R2가 회전 가능한 위치로 옮기는 계획을 G=3으로 낸다.
- 걸쳐 놓인 화물을 돌려 X가 줄면 G에 반영된다.
- 자리가 없던 대기 입고가 R2 뒤 `plan_placement`에서 READY가 된다.
- F만 늘고 G=0인 계획은 자동 실행되지 않는다.
- R3: 추가 이동은 반출 뒤 복귀 단계에만 들어간다. 다른 반출이 대기 중이면 추가 이동 없이 R1 계획만 낸다.
- R0·R1·R2의 판정 함수가 같은 표를 만족한다. 순서 판정 표를 그대로 매개변수 시험으로 둔다.
- 작은 고정 배치에서 전수 탐색 결과와 일치한다(기존 oracle 시험 방식).

실물 수용은 별도다. 시뮬과 실물 A 팔로 R2 계획 하나를 끝까지 수행하고 관측으로 목표 배치를 확인해야 한다.

## 하지 않는 것

- 허용 범위 밖의 자동 실행. R2 외 업무(입고·반출)의 자동 실행.
- Harbor가 팔 기구학으로 회전·도달 가능 여부를 직접 계산하는 것(ROSY 기하 소유, ADR0013).
- ETA·벽시계 일정, 고장 예측 기반 재배치.
- 여러 입고를 묶은 최적화.
- 실행 중 남은 단계 교체.
