# 버전이 있는 구역·칸 편집

HarborLogi 관리자는 구역을 추가·삭제하고 각 구역의 표시 이름, 역할, 행·열·높이, 화면 위치를 편집한다. 주 보관 구역 `yard`의 구조 ID는 유지하고 칸 ID는 명시적으로 관리한다. 보조 구역은 기존 행·열 주소 규칙을 사용한다. 화물의 1×1·2×1·3×1 점유와 0/90도 회전 규칙은 맵 크기와 독립이다.

## 소유권과 저장

편집은 설치 기준 Condition을 복제한 초안이다. 검증 후 새 Condition을 등록하며 기존 관측·계획·명령은 당시 Condition을 계속 참조한다. 등록 시 빈 관측을 만들거나 기존 화물 좌표를 새 맵의 사실로 옮기지 않는다. 새 기준의 계획은 새 기준으로 수집한 전체 관측이 필요하다. Django의 기존 불변 모델과 JSON payload를 사용하며 별도 활성 맵 전환은 만들지 않는다.

기존 `yard_layout`, `spatial_areas`, `temporary_bays`, `outbound_stand`를 유지한다. `storage_areas`는 일반 보관 구역 집합, `area_presentation`은 구역별 `{label,x,y}` 표시 좌표다. 표시 좌표는 로봇 좌표가 아니다. 구역 사각형은 화면에서 겹치지 않는다. 예전 payload에는 기본 보관 구역과 자동 표시 배치를 적용한다. 선택 키 `slot_cells`는 고정 컨테이너 자리의 폭(칸 수)이다. 값이 있으면 모든 구역의 열 수가 그 배수여야 하고, 계획은 자리 경계에서만 화물을 놓으며 화면은 자리 단위로 보인다(ADR 0026). 맵 편집은 이 값을 그대로 복제한다.

## 편집과 검증

관리자 전용 `/settings/maps/new/`, `/settings/conditions/<id>/map/`에서 새 초안/복제를 제공한다. 같은 경로의 `validate/`는 CSRF 보호 JSON 검증이며 저장하지 않는다. 서버가 DTO의 정확한 키, 역할, 주소, 크기, 겹침을 검증하고 정규화된 맵과 미관측 3D 장면을 반환한다. 저장은 같은 검증을 반복하고 초안 fingerprint를 확인한다. 이름과 교정 참조를 명시적으로 입력한다. 클라이언트가 팔 도달 범위나 실행 정책을 지정할 수 없다.

행·열 각 12, 높이 6, 구역 16, 총 칸 4096, 화물 256을 초기 작업량 상한으로 둔다. 이 수치는 실물 안전 한계나 성능 보장이 아니다. 탐색은 상태와 후보 생성 예산을 함께 제한하고 한도 초과는 부분 이동 없이 HOLD로 반환한다.

칸 확대 시 같은 행·열의 기존 칸 ID를 보존한다. 제거·이름 변경·물리 구조 변경에 걸리는 팔 도달 범위/이동 참조를 상속하지 않는다. 새 구역/칸은 도달 가능으로 자동 승인되지 않는다. 표시 이름·화면 위치 변경은 물리 구조 변경과 구분한다. 일반 보관 구역의 화물도 반출·복원 계획 대상이지만 임시 구역 역할과 도달 범위는 별도다.

## 화면

왼쪽 구역 목록, 중앙 기존 Three.js 모듈을 재사용하는 맵 미리보기, 오른쪽 선택 구역 속성을 제공한다. 추가·크기 조정·역할/이름·위치 편집 후 서버 검증 결과와 제거된 참조를 보여준다. 미관측 맵에는 화물이 없다는 의미의 빈 칸 대신 `배치 미관측`을 표시한다. 원본 기준, 검증 상태, 변경 요약, 등록 결과를 계속 식별할 수 있게 한다.

재고 화면은 Condition 선택과 Observation 선택을 분리한다. 관측이 없는 기준도 정의된 맵을 확인할 수 있지만 계획/화물 가상 편집은 제공하지 않는다. 과거 관측을 선택하면 그 관측에 고정된 맵을 사용한다.

## ROSY 경계

맵 등록은 실물 교정·설치 승인·실행 바인딩을 대신하지 않는다. `grid-placement-v1`과 `SPATIAL_EXECUTION_BINDINGS_REQUIRED` 실행 차단을 유지한다. Harbor는 업무·배치·계획을 소유하고 ROSY는 실행 및 로봇 상태를 소유한다.

## 사용자 요구와 시스템 수용 조건

아래는 이번 사용자 요청의 공개 구현 추적이다. 팀 UR/SR 원문·ID·승인 상태는 비공개 정본을 대신하지 않는다.

| 사용자 요구 | 시스템 조건 | 검증 |
|---|---|---|
| 구역과 칸을 직접 늘리고 줄인다 | 관리자만 구역/역할/크기/칸 ID/표시 위치를 편집하고 서버가 전체 구조를 검증 | 편집 DTO와 관리자·CSRF 시험, 실제 브라우저 확대·추가·등록 |
| 3×3×3은 초기 예이며 확장이 가능하다 | 행·열·층을 설정에서 읽으며 UI·관측·계획의 동일 기준을 사용 | 확장 맵의 도메인·장면·재고 회귀 시험 |
| 화물 하나가 여러 칸을 쓴다 | 화물 크기 revision·0/90도 방향·전체 지지/겹침 규칙은 맵 크기와 독립 | 다칸 도메인 및 기존 3D 가상 편집 시험 |

| 확장 구역도 반출/복원을 검토한다 | storage 역할의 출발/복원 허용, 임시 역할·도달·이동 정책 별도 검증 | 추가 보관 대상·복원·도달 미검증 HOLD 시험 |
| 맵을 보고 이해한다 | 구역 경계·적재 높이·칸 주소와 표시 이름, PC/태블릿/모바일 대응 및 평면 대안 | 실제 렌더·너비별 overflow·WebGL 실패 대안 |
