# 자동 운전 상황판과 실제 앱 대응

상태: 2026-11-21 사용자 결정에 따른 목표 설계. **화면·실행 구현 완료를 뜻하지 않는다.** WP01 문서 범위이며, 자동 실행은 [ADR0034 제안](../adr/0034-automatic-operation-permission.md) 수락과 후속 구현 전까지 열지 않는다. 역할·접근 목표는 [설계34](34-role-scenario-access-and-menus.md)를 따른다.

## 기준과 적용 순서

`runs/PLAN.md`의 「사용자가 이미 정한 것」·「공통 규칙」이 시안보다 우선한다. 참고는 `runs/mock/app/components.md`, `brief-v3.md`, `brief-v4*.md`, `REPORT-v4.md`, `ia.md`, `cell-photo-20261107.jpg`, `harbor-control-mockup.html`이다. 시안의 예시 수치·시각·인식 결과는 실제 자료가 아니다. 오래된 시안의 9개 메뉴, 진행률, 자리 결정 버튼, 가짜 정지·장비·인식 상태를 옮기지 않는다.

실제 토큰은 `harbor/web_assets/tokens.css`와 `design/tokens.json` 체계를 확장하고 `python3 tools/design_tokens.py --check`로 검사한다. 3D는 실제 `harbor_web/static/harbor_web/yard-3d.js`와 vendored three 0.186을 확장한다. 시안의 three r128 CDN·색 토큰·MOCK 자료·역할 전환을 이식하지 않는다.

## 작업 상태 세 가지와 예외

내부 상태는 바꾸지 않고 표시만 통일한다. 실제 Command choices는 `harbor_web/command_models.py`에서 확인했다. 다음 표는 WP02의 표시 계약이며 Fleet 접수가 물리 실행 시작이라는 뜻은 아니다.

| 내부 출처 | 기본 작업 표시 | 부가 설명·주의 |
|---|---|---|
| Command `PREPARED` | 대기 | 준비됨. 실제 시작으로 표시하지 않는다 |
| Command `DISPATCHING`, `RECONCILED` | 진행 중 | 제출·실행 결과 확인을 포함한 업무 진행. 팔이 움직인다는 증거로 쓰지 않는다 |
| Command `COMPLETED` | 완료 | Harbor 업무 완료. Fleet 실행 종료만으로 올리지 않는다 |
| Command `UNKNOWN`, `BLOCKED`, `CANCEL_PENDING` | 처리할 것(예외 표시) | 세 기본 상태에 억지로 넣지 않고 사유·담당 조치를 표시한다 |
| Command `CANCELLED` | 대기 + 취소됨 | 끝난 실행 이력으로 보존. 완료 실적에는 넣지 않는다. 다시 할 업무는 최신 유효 상태로 판단 |
| Command 없는 최신 유효 Plan `READY` | 대기 | 추천 계획이며 실행 사실이 아니다 |
| Plan `HOLD`, 기준 변경·만료·계획 없음 | 대기 + 진행 불가/재검토 사유 | 처리가 필요한 항목은 처리할 것에도 연결. 내부 영문은 접힘 안 |

끝난 **개별 이동**에 실제 종료 근거가 있고 다음 이동 시작 근거가 없으면 「완료 · 다음 작업 대기 중」을 쓴다. 작업 전체가 끝났다는 뜻이 아니므로 오늘 완료에 더하지 않는다. 현재 일이 없으면 「대기」다. 상태 띠에는 「상태는 ROSY 실행 결과로 바뀜」을 한 번 둔다. 퍼센트·이동 N/M 진행 막대는 없다. 계획 재생 애니메이션을 실제 실행 진행으로 해석하지 않는다.

## 오늘 일정 N/M 완료

- 계산 시점의 앱 현지 날짜(설정된 시간대)의 자정부터 다음 자정 전까지를 오늘로 한다.
- N은 **오늘 업무 완료가 기록된 등록 업무 수**다. `Command.COMPLETED`와 그 저장에 대응하는 `Audit.action='command.completed'` 시각을 출처로 삼는다. 기존 `operations.py`처럼 같은 Order의 중복 완료 Command를 중복 계산하지 않는다. Order 수정 시각이나 로봇 실행 종료 시각으로 대체하지 않는다.
- M은 **N + 아직 끝나지 않은 등록 업무 수**다. 이전 날짜에 등록한 미완료 업무도 포함한다. 과거 날짜에 이미 완료한 업무는 양쪽에서 제외한다.
- 등록 업무는 Order 단위다. 입고·반출·재배치를 포함하고, 그 안의 재취급·복귀 이동은 별도 업무로 더하지 않는다. 계획 버전·Command 재시도·예시 일정 행도 더하지 않는다.
- 막힘·결과 불명·취소 요청 중인 업무는 미완료에 남긴다. 취소된 Command는 완료가 아니다. 취소 뒤에도 등록 Order가 남으면 미완료다. 등록 업무 자체를 철회하는 별도 계약을 만들지는 않는다.
- 실제 업무가 생기지 않은 재배치 「건너뜀」·「할 일 없음」은 양쪽에서 제외한다. 자료가 없으면 `0/0 완료`이며 임의의 예정 건수를 만들지 않는다.
- 「오늘 일정 N/M 완료」는 숫자만 쓴다. 막대·퍼센트가 없고, 최근 24시간 처리량과 별개다. 완료 감사 기록이 빠진 자료를 임의의 오늘 실적으로 채우지 않는다.

## 상황판 배치와 야드 표시

운전 상태 → 오늘 처리량 → 처리할 것(있을 때만) → 지금 하는 일·다음 다섯 일 → 야드:탑뷰 **1:1** 순서다. 좁으면 위아래로 놓는다. 미니 평면은 화살표 없이 출발·도착을 같은 배경으로 표시하고 갈 자리에 옅은 화물 번호를 둔다. 반출 순번 동그라미와 「2행×3열×3층」 크기 설명은 넣지 않는다. 야드 상세의 선택 예정에는 이동 화살표와 3D를 연결할 수 있다.

현장 고정 자리 표시는 [ADR0035 제안](../adr/0035-operating-terms-and-yard-display.md)을 따른다. 논리 야드 3행·행당 2자리를 화면에서 **2행×3열**로 전치한다. 실제 `(r행, s번째 자리, 층)` → 화면 `(s행, r열, 층)`, 1행은 위·1열은 왼쪽이다. 예: 실제 3행 2번째 자리는 「야드 2행 3열」이다. 임시 판 A·B는 각각 1·2·3레인을 왼쪽부터 가로 나란히 놓고 「임시 판 A 1레인」으로 쓴다. 층이 필요한 상세는 뒤에 층을 붙인다.

평면·3D·탑뷰의 자리 선택이 같은 실제 주소를 가리켜야 한다. 계획 좌표·주소·`arm_reach`·설치 binding은 바꾸지 않는다. 팔 A·B는 모두 야드 전체, 임시 판은 자기 쪽만, 반출대는 팔 A 쪽 하나다. 카메라에 인식 계약이 없으면 자리 대응·인식 표식을 합성하지 않는다.

## 출처 없으면 끄거나 연동 전

| 항목 | 출처가 마련되기 전 표시·행동 |
|---|---|
| 비상 정지 | 꺼진 「ROSY Fleet에서 정지 · 연동 전」. Harbor 클릭으로 정지 성공을 연출하지 않는다 |
| 장비 상태·배터리·센서 | 「장비 상태 연동 전」. Command로 실제 장비 정상·가동을 추정하지 않는다 |
| 자리별 ROSY 인식·차이 표식·「야드와 다른 곳 N」 | ADR0032 계약 수용 전에는 끈다. 실제 탑뷰 프레임 제공과 자리 신원 인식은 별개 |
| 입고 자동 결정·반출 순서 자동 토글 | 계약·허용 정책 전에는 끈다. 「알고리즘이 정한 순서」 대신 「추천 순서」 |
| 예정 시각·희망 시각·재배치 창 | 출처 계약 전에는 연동 전 또는 숨김. 다음 일은 순서만, 지난 일은 기록 시각만 |
| 「멈춤」 운전 상태 | 실제 상태 출처 전에는 쓰지 않는다. 예외 발생이나 화면 새로고침 중단을 장비 정지로 부르지 않는다 |
| 입고가 섞인 연쇄 3D | 끈다. 반출 연쇄만 검증된 단계로 재생 |
| 자동 운전 실행 | ADR0034 수락·권한·계약 시험 전에는 비활성. 화면 문구가 실행 권한을 만들지 않는다 |

「처리할 것 없음」과 실행기 켜짐은 서로 다른 사실이다. WP16에서 실행기 출처를 읽기 전에는 「자동 진행 켜짐」을 만들어 내지 않는다. ROSY 사건 미도착은 기본 **10분**을 설정값으로 둔다. WP17에서 기존 설정 관례를 먼저 확인하고, 새 환경변수가 필요하면 `docs/execution.md`에 한 줄을 기록한다. WP01에서는 설정·환경변수를 추가하지 않는다.

## 용어·사람 판단·수용 조건

운영 기본 화면의 「관측·원본·인계·대조·회차·#번호·READY/HOLD」는 지원용 `<details>` 안에서만 허용한다. 기록 기본 행은 사람 문장, 출처·식별자·본문은 접힘이다. 사람이 판단한 결과는 자동 측정과 구분하며 확인자·시각·대상·근거를 남긴다. 반입은 [ADR0036 제안](../adr/0036-human-review-of-rosy-recognition.md)의 좁은 경로부터 연결한다.

후속 구현은 상태 전부·오늘 날짜 경계·Order 중복·완료 후 다음 대기, 메뉴 역할×경로×POST 권한, 실제 주소와 2D/3D 자리 일치, 연동 전 비활성·빈 자료, 모달 키보드·포커스·좁은 화면을 시험한다. 완료 판정·Fleet 승인·신원·근거 검증을 표시 문구 때문에 줄이지 않는다. 공통 검사는 `bash runs/test_all.sh`, `python3 -m unittest discover -s tests`, `python3 tools/design_tokens.py --check`다. 이 문서의 검증 결과는 `runs/REPORT.md`에 기록한다.
