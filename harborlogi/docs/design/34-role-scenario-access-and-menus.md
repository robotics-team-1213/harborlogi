# 역할 시나리오별 화면 권한과 메뉴

상태: **2026-11-21 사용자 결정에 따른 목표 설계**. 2026-11-14의 그룹 메뉴·접근 행렬을 아래 목표로 갱신한다. 현재 `harbor_web/access.py`는 여전히 기존 그룹 메뉴와 권한을 갖는다. WP01은 문서만 바꾸며, 새 메뉴·처리할 것·현장 야드 접근은 WP04~WP06·WP13의 구현과 HTTP 권한 시험이 필요하다.

사람 책임의 기본은 [설계01](01-roles-and-workflows.md), 기존 경로·동작 계약은 [설계13](13-product-web-surface.md), 자동 운전 화면 목표는 [설계35](35-control-dashboard.md)다. 기존 문서와 메뉴·역할 목표가 충돌하면 이 문서의 2026-11-21 목표를 따르되, 구현이 이미 바뀌었다고 해석하지 않는다. 실제 인원·겸임 담당자를 합성하지 않는다.

## 1. 역할과 기본 진입

| 역할 표시 | 계정 group | 맡는 일 | 기본 진입 |
|---|---|---|---|
| 운영 | `operator` | 자동 진행을 보고 순서·자리 변경, 취소, 예외 처리 | `/` 상황판 |
| 현장 | `field` | 배정된 대상의 적재면 확인·실행 단계 사람 확인 | `/alerts/` 처리할 것 |
| 관리 | `admin` | 상황 열람, 계정·설치 기준·ROSY 연결 설정 편집 | `/` 상황판 |
| 조회 | `viewer` | 허용된 화면 읽기 | `/` 상황판 |
| Fleet 승인·운영 | Harbor group 아님 | ROSY의 승인·정지·복구 | ROSY Fleet |

겸임은 group을 함께 부여한다. 관리가 운영 쓰기 권한을 자동으로 얻지 않는다. ROSY 로그인 역할 원본과 기존 인증 경계를 유지한다. 역할 선택 상자는 시안 전용이며 운영 계정 권한 전환 기능을 만들지 않는다.

## 2. 일곱 메뉴의 목표 접근 행렬

○ 열람, ● 해당 역할의 쓰기 포함, — 메뉴 없음·기본 접근 불가. 쓰기는 아래 3절의 범위에 한정한다.

| 메뉴(순서) | 경로 | 조회 | 운영 | 현장 | 관리 |
|---|---|---|---|---|---|
| 상황판 | `/` | ○ | ○ | — (첫 진입은 처리할 것으로 이동) | ○ |
| 작업 | `/work/` | ○ | ● 예외 도구 | — | ○ 읽기만 |
| 야드 | `/inventory/` | ○ | ● 권한 있는 예외 도구 | ○ | ○ |
| 처리할 것 | `/alerts/` | — | ● | ● 자기 대상의 현장 확인만 | ○ 읽기만 |
| 기록 | `/records/` | ○ | ○ | — | ○ |
| 설정 | `/settings/` | — | — | — | ● |
| 도움말 | `/workflow/` | ○ | ○ | ○ | ○ |

전체 메뉴는 위 일곱 개의 평면 목록이다. 역할이 열 수 있는 항목만 순서대로 보인다. 현장은 **처리할 것·야드·도움말** 세 개이고 첫 화면이 처리할 것이다. 메뉴 배지는 실제 처리 필요 건수만 사용하며, 자리 인식 계약이 없는 수치를 합성하지 않는다. 「개발 중 기능」·「기능 대응표」는 없다.

기존 반출·화물·계획·현장 확인·재배치 화면은 메뉴에서 빼고 `Page.group=None` 상세로 연결한다. 메뉴 숨김만으로 접근을 통제하지 않는다. 경로별 GET·POST 서버 권한도 검사한다. 코드의 `PAGES`가 구현 후 단일 원본이고, 도움말·설정의 역할표도 이를 읽는다.

## 3. 동작 권한과 상세 경로

| 동작·상세 | 목표 권한·제약 |
|---|---|
| 화물·요청·계획·반출·재배치 상세 열람 | 조회·운영·관리. 현장은 자기 확인에 필요한 상세만 기존 대상 검사 아래 허용 |
| 화물·요청 등록·변경, 반출 순서·입고 대안 자리, 계획 제안·취소 | 운영 전용 예외 도구. 관리·조회는 읽기만, 현장은 불가. 서버 검증·Fleet 승인 유지 |
| 반입 인식 기명 판정 | ADR0036 첫 범위는 운영만 UNREADABLE 확인. 현장·관리·조회는 이 폼에서 보기만 |
| 적재면 확인·실행 단계 사람 확인 | 현장·운영의 기존 조건 유지. 현장은 자기 배정·현재 확인 단계·설정 켜짐·대상과 신선도 검증. 관리·조회는 제출 불가 |
| 현장 대상 배정 | 운영만. 현장 확인 상세는 `/field/`·`/field/<id>/`, 배정은 `/field/new/` 유지 |
| 작업 상세 | `/work/<pk>/`·`/work/n…/` 유지. 현장 단독은 허용된 사람 확인 단계만, 명령 제출·취소 권한 없음 |
| 기록·비교 | 기본 화면 읽기 전용. 기존 측정 등록은 운영의 별도 상세 도구(`/records/measurements/new/`)로 유지 |
| 설치 기준·맵·야드 자료 등록·Fleet 연결 설정 | 관리 전용. 설정 아래에서 기존 상세로 연결 |
| 계정 관리 `/admin/` | 관리 역할 + active staff만 링크·접근. staff가 아니면 필요한 권한 안내 |
| 자동 운전 허용·실행 | ADR0034 제안 수락·별도 권한/계약 구현 전에는 새 허용 동작 없음 |
| 비상 정지 | 「ROSY Fleet에서 정지 · 연동 전」으로 비활성. 실제 정지·복구는 Fleet 소관 |

조회 역할은 모든 허용 화면에서 읽기만 한다. 현장 야드·탑뷰 조회 권한 확대는 WP06에서 프레임 프록시까지 검사해야 한다. 인식 판정과 적재면 확인, 실행 단계 사람 확인은 서로 다른 행위다.

## 4. 역할 시나리오와 안내

| 역할 | 기본 흐름 | 예외와 다음 조치 |
|---|---|---|
| 운영 | 상황판 → 작업·야드에서 진행과 다음 일 보기 | 처리할 것 → 사유 확인 → 권한 있는 예외 도구. 자동 실행 활성화는 ADR0034 이후 |
| 현장 | 처리할 것 → 자기 확인 대상 → 적재면/실행 단계 결과 제출 | 야드로 위치 확인, 불일치·확인 불가는 사실대로 제출 |
| 관리 | 상황판·작업·처리할 것 읽기 → 설정 | 설치·연결·역할 수정. 업무 실행은 운영 역할 필요 |
| 조회 | 상황판 → 작업·야드·기록 읽기 | 도움말에서 담당 확인, 쓰기 없음 |

도움말은 내 역할의 할 일 세 줄을 먼저 보여 준다. 권한 없는 다음 단계는 링크 대신 담당 안내다. 403 복귀는 읽을 수 있는 상황판, 현장 단독은 처리할 것, 역할 없음은 역할 미배정 안내와 비밀번호 변경·로그아웃이다. 모든 역할에 하나의 복귀 경로를 강제하지 않는다.

## 5. 구현 위치와 확인할 것

현재 원본은 `harbor_web/access.py`(PAGES·MENU_PAGES·nav_groups·persona_names), 각 view의 권한 검사, `auth.py`다. 기존 메뉴는 `presentation.py`·`base.html`, 도움말은 `scenarios.py`·`workflow.html`, 403은 `403.html`, 관리 계정 링크는 `settings.html`에 있다. WP01에서 이 코드를 변경하지 않는다. 후속 화면 로직은 새 모듈로 두며 공통 규칙에 따라 `presentation.py`를 건드리지 않는다.

기존 `tools/product_preview.py`의 합성 역할별 계정은 개발 DB 검토용이다. 계정·비밀번호는 문서·공개 저장소에 넣지 않는다. 운영 담당자를 합성하지 않는다.

후속 수용은 역할×등록 경로 GET/POST, 상세 대상·배정 제한, 겸임, 역할 없음, 403 복귀, 비staff 관리 링크, 현장 야드·프레임 열람, 메뉴 일곱 개·역할별 순서·배지·도움말/설정 표 일치를 검사한다. 기존 시험 `test_access_policy.py`·navigation·access_fallbacks·preview_personas를 목표에 맞춘다. 메뉴 구현 완료와 실제 Fleet 현장 수용은 별도로 보고한다.
