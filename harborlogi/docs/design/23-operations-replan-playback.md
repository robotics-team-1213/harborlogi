# 물량·재취급 경로·재계획 비교·느린 재생

[ADR0011](../adr/0011-operations-replan-explanation-and-playback.md)에 따른 읽기 모델과 화면 설계다. 기존 계산기·자동 재계획·실행 권한은 바꾸지 않는다.

## 첫 화면이 답할 질문

1. 선택한 관측에 실제로 기록된 화물이 몇 개체이며 어느 구역의 몇 칸을 쓰는가?
2. 전체 등록 입고/반출 지시는 몇 건이며, 선택 원본의 현재 제안에 얼마의 재취급·반출·복귀 작업이 있는가?
3. 최신 기준으로 재검토할 것은 무엇이고 원래 실행을 대조할 것은 무엇인가?
4. 실제 완료량을 입증하는 업무 근거가 있는가?

관측 selector는 출처·revision·시각·provenance를 표시한다. 오래된 원본·같은 출처의 새 관측 여부를 명시하고 Condition도 선택 관측에 고정한다. 등록 지시와 원래 인계는 전체 범위, 재고와 계획 전망은 선택한 관측 범위임을 표시한다. 화물 개체 수와 점유 격자 수를 구분하고 보관/임시/반출대·holding을 나누어 보여준다.

예상 작업량은 요청별 최신 Plan 한 건을 검토한다. 인계된 요청은 Command의 원래 Plan을 별도로 표시하며 새 제안 합계에서 제외한다. HOLD·오래됨·지시 변경·다른 관측/조건은 유효 이동 합계에 넣지 않는다. 독립 제안의 합계를 공동 일정이나 실제 실적으로 표현하지 않는다. 입고 추천에는 가상 source 이동이 없으므로 실제 이동 횟수로 환산하지 않는다.

인증된 업무 완료 producer가 없으면 실제 완료량·처리율·시간당 물동량은 미집계다. 모형 개체나 점유 칸에서 TEU·ton을 추측하지 않는다. 관측이 없으면 재고를0으로 표시하지 않는다.

## 어떤 화물을 분리하고 다시 쌓는가

반출 작업 공간의 화물별 경로는 분리할 개체, 목표 반출 개체, 복귀/재적재 이동을 구분한다. 각 개체의 관측 출발·임시 위치·최종 위치, 단계·담당/대안 팔과 크기 원본을 보여준다. 한 화물이 여러 칸을 점유해도 원자 개체 하나로 센다. 여러 칸을 잘라 분리하는 동작을 만들지 않는다.

화물별 경로 위의 ‘배치에서 전체 순서 보기’ 버튼 하나가 같은 원본의 야드 보기로 이동해 관측 배치부터 마지막 단계까지 차례로 재생한다(KAN-115, 2026-11-05). 화물마다 두던 ‘배치에서 C2 보기’ 링크와 단계마다 두던 재생 버튼은 순서가 한눈에 보이지 않아 없앴다. 특정 화물은 3D의 화물 선택으로 고른다. 3D가 없으면 야드 원본을 읽는 동선으로 남는다. 입고 추천은 관측 출발 위치가 없음을 표시하고 예상 목적 위치만 보여준다.

## 재계획 전후의 차이

Plan의 `previous_plan_id`가 같은 요청의 과거 계획일 때 추가·제외·경로 변경·유지를 개체별로 비교한다. 출발/목적 행·열·층·방향, 단계·역할·팔·크기 원본을 당시 기록으로 비교한다. 지시 revision·관측·Condition·footprint를 재해석하지 않는다. 제외는 새 제안의 변화이며 원래 실행 취소가 아니다. HOLD는 제안 이동을 표시하지 않는다.

## 재생의 의미

기본 이동당4.5초이며0.5배는9초,2배는2.25초다. 들어 올림·수평 이동·내려놓기, 화물 ID·출발/도착·진행을 표시한다. 계획 재생과 로컬 가상 편집 재생을 구분한다. 유효한 편집 이력을 순서대로 재생하며 중지 시 최종 draft로 돌아온다. 재생 중 편집 입력은 잠가 중간 상태를 편집 결과로 만들지 않는다.

같은 위치의 방향 비교는 즉시 전환하며 회전 보간을 만들지 않는다. 관측 출발이 없는 새 입고 화물은 목적 배치 비교를 기본4.5초 동안 보여주고 가상 픽업 경로를 만들지 않는다. 이동 애니메이션 선택은 OS의 reduced motion을 기본으로 따르며 사용자가 직접 바꿀 수 있다. 애니메이션이 꺼져도 전체 계획·가상 편집 재생은 단계별로 기본4.5초 간격을 유지한다. 수동 단계 선택은 즉시 비교할 수 있다. 재생은 실제 경로·작업 시간·물리 안정성 검증이 아니며 관측/Plan/Command를 생성·수정하지 않는다.

## 수용 추적

관제에서 선택한 관측은 반출 목록의 검색·검색 해제와 업무 상세 진입에서도 유지한다. 저장된 계획의 원본은 바꾸지 않는다. ‘배치에서 전체 순서 보기’는 재생 중이면 멈춘 뒤 관측 배치부터 다시 재생하며, 재생 중지 버튼으로 멈출 수 있다. 비교의 ‘변경 항목만 보기’는 유지된 경로를 숨기며 변경이 없으면 빈 결과의 이유를 표시한다. JavaScript가 없으면 기존 경로·비교 표를 그대로 읽는다.

사용자가 계획을 확정한 뒤의 제출 흐름은 [ADR 0012](../adr/0012-user-confirmed-command-dispatch.md)를 따른다. Harbor는 확정 POST에서 바로 제출하고 기존 API가 요구하는 별도 Fleet 승인 상태를 숨기지 않는다.

| 재생성된 계획이 무엇을 바꿨는지 안다 | 이전/현재 경로와 추가/제외/변경/유지 | 경로 변경·HOLD 제외·다른 요청 이전 Plan 거절·과거 원본 |
