# ADR 0017: 규칙이 정하는 화물 재배치 판단과 결정 모델 협의

날짜: 2026-10-31

상태: 수락(2026-10-31, 사용자 결정 "나머지도 처리해").
- 구현됨: R2 계산 단독 판단 `plan_rearrangement`(`harbor/spatial.py`)와 단위 시험.
- 구현됨: 허용 범위 저장, 유휴 업무 실행기의 자동 실행 조건 검사, `REARRANGE` 지시 종류, 화면.
- 구현 전: 결정 모델 협의(Q10 provider 미정), 다칸 이동의 칸 단위 설치 대응(없으면 Command 생성 전에 멈춘다). 상세는 설계32 구현 상태.
- 확장하는 ADR: ADR0010·0013·0014.
- ADR0012에는 예외를 하나 둔다(결정 4).
- 기준의 상세는 [설계32](../design/32-cargo-rearrangement-criteria.md)가 정본이다.

## 배경

Harbor는 지금 두 곳에서만 반출 순서에 따라 위치를 고른다.
- 입고 위치 선택(`plan_placement`)
- 반출 뒤 재취급 화물의 복귀 위치 선택(`plan_spatial`)

이미 쌓인 화물을 순서·방향에 맞게 다시 쌓는 업무는 없다. 두 계산은 순서 모르는 화물을 다르게 센다.

2026-10-31 사용자는 다음을 요구했다.
- 재배치 기준을 세운다.
- 회전을 포함해, 얻는 것이 크면 허용한다.
- 판단은 결정 모델과의 협의나 계산을 거치되, 규칙에 따라 내린다.
- 독립 재배치는 자동 실행한다.

ADR0014는 AI가 검증된 후보를 설명하거나 후보 ID를 제안할 수 있다고만 열어 두었다. 외부 AI 호출은 추가하지 않았다.

## 결정

### 1. 재배치 종류

| 구분 | 내용 | 결정 |
|---|---|---|
| R0 | 입고 위치 선택 | 유지 |
| R1 | 반출 뒤 복귀 위치 선택 | 유지, 반출대 회전 추가 |
| R2 | 반출 지시 없는 독립 재배치 | 새로 연다. 허용 범위 안에서 자동 실행 |
| R3 | 반출 중 다른 화물까지 정리 | 조건부로 연다. 반출 뒤 복귀 단계에만 넣는다 |

### 2. 판단은 세 층으로 나눈다

| 층 | 하는 일 | 결정 권한 |
|---|---|---|
| 규칙 | 합법성·안전·실행 조건을 판정한다. 합법성은 겹침·지지·도달·허용 이동·설치된 회전 대응, 실행 조건은 개선량 G·k·`max_moves`·자동 실행 조건이다 | 최종 통과·거절. 다른 층이 바꿀 수 없다 |
| 계산 | 결정적 탐색으로 완전한 후보 계획을 만들고, 설계32의 사전식 목표로 순위를 매긴다 | 기본 추천안 |
| 결정 모델 | 후보를 비교·설명하고, 새 후보를 제안하거나 거부 의견을 낸다 | 제안과 거부만. 승인 권한은 없다 |

결정 모델은 Harbor 쪽 구성 요소다. ROSY Decision이나 Fleet에 항만 규칙을 넣지 않는다(ADR0013).

### 3. 계산과 결정 모델의 협의 절차

한 번의 재배치 판단은 최대 3회의 협의로 끝난다. 정해진 시간 안에 끝나지 않으면 계산 결과만으로 판단한다.

1. 계산이 결정 모델에 다음을 넘긴다.
   - 현재 배치와 반출 순서
   - 상위 후보 5개, 각 후보의 지표(U·B·N·X·F·이동 수·회전 수)
   - 적용한 규칙
2. 결정 모델은 다음 중 하나를 돌려준다. 설명 문장은 선택이다.
   - `accept(후보 ID)`
   - `propose(이동 목록)`
   - `veto(이유)`
3. 규칙과 계산이 응답을 처리한다.
   - `propose`는 계산 후보와 똑같이 처리한다. 합법성 검사와 전체 이동 재생을 거치고 같은 목표로 점수를 매긴다.
   - 거절되면 거절 이유를 다음 협의에 넘긴다.
4. 최종안은 다음 규칙으로 정한다.
   - 결정 모델의 제안은 계산 최선안보다 사전식으로 엄격히 좋을 때만 계산 최선안을 대신한다. 같으면 계산안을 쓴다.
   - `accept`는 그 후보가 규칙을 통과했을 때만 효력이 있다. 계산 최선안이 아닌 후보를 고르면 자동 실행하지 않고 사용자 확정으로 넘긴다.
   - `veto`는 자동 실행을 멈추고 사용자 확정으로 넘긴다. 결정 모델은 더 보수적으로만 만들 수 있고, 규칙을 완화할 수는 없다.
5. Plan은 다음을 저장한다. 과거 Plan을 열면 같은 의미로 보인다.
   - 협의 회차별 입력 요약·응답·판정·거절 이유
   - 최종안을 낸 쪽(계산 / 결정 모델)
   - 결정 모델 식별자와 버전

결정 모델이 없거나 응답하지 않거나 형식이 틀리면 계산만으로 판단한다. 이 경우 업무가 멈추지 않는다. 모델의 문장이나 자신감은 실행 가능성·우수성의 근거가 아니다. 모델 출력은 신뢰하지 않는 입력으로 다루고 검증한다.

### 4. R2 자동 실행과 ADR0012 예외

ADR0012는 "자동 계획 생성은 사용자 실행 확정을 대신하지 않는다"고 정했다. 이 ADR은 R2에 한해서 사용자가 확정하는 대상을 개별 계획에서 **허용 범위**로 바꾼다.

- **허용 범위의 내용:** 실행 권한이 있는 사용자가 허용 범위를 켠다. 허용 범위에는 다음이 들어간다.
  - k, `max_moves`
  - 유효 기간(기본 8시간)
  - 하루 최대 실행 횟수(기본 20회)
- **허용 범위의 기록:** 켜고 끈 이력은 지우지 않는다.
- **자동 실행 조건:** 허용 범위가 켜져 있고 다음을 모두 만족할 때만 업무 실행기가 Command를 만든다.
  - 반출 지시가 진행 중이거나 대기 중이 아니다.
  - 다른 Command가 진행 중이거나 결과 불명이 아니다.
  - 관측이 신선하고, 계산에 쓴 revision이 실행 직전 revision과 같다.
  - holding이 없다.
  - 결정 모델의 `veto`가 없다.
- **반출이 먼저다:** R2가 실행 중일 때 반출 지시가 들어오면 남은 이동을 새로 시작하지 않는다.
- **범위 밖 업무:** 입고·반출·R3는 이 예외에 들어가지 않는다. 기존 사용자 확정을 따른다.

### 5. 회전과 그 밖의 허용

- 회전·이동 종류·범위 확장은 지표를 개선하면 허용한다. 막는 이유는 물리 불가와 안전뿐이다.
- 회전이 실행 가능한지는 설치된 (이동, 방향, 팔) 대응(설계29)에 있을 때만 인정한다. Harbor는 팔 기구학을 계산하지 않는다.
- 회전으로 얻는 것은 다음 세 가지다. 셋 다 개선량 G에 넣는다.
  - 반출 불가 화물(U) 해소
  - 대기 입고의 자리 확보
  - 교차 지지(X) 감소
- 회전 수는 효과가 같은 계획 중에서만 비교한다.
- 야드→야드 직접 이동을 설치 기준에 넣는다.

### 6. 순서 판정 통일

R0·R1·R2·R3는 같은 순서 판정 함수를 쓴다. 이 함수는 (막힘, 미확인)을 돌려준다.
- 반출 지시가 없는 화물은 미확인이다.
- 같은 우선순위 그룹에서 sequence를 고정하지 않은 화물끼리는 무관이다.

목표 함수가 바뀌므로 objective version을 올린다.

## 고려한 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| 결정 모델이 최종 결정 | 실행 가능성과 우수성을 검증할 수 없다. ADR0014의 "모델의 자신감은 근거가 아니다"에 어긋난다 |
| 계산만 쓰고 모델 없음 | 규칙·지표로 잡지 못한 상황을 걸러낼 길이 없다. 사용자에게 설명할 수단도 없다. 대신 모델이 없을 때의 대체 경로로 둔다 |
| ROSY Decision에 재배치 판단을 맡김 | 항만 규칙이 플랫폼으로 샌다(ADR0013) |
| R2도 계획마다 사용자 확정 | 사용자가 자동 실행을 선택했다. 안전은 허용 범위와 자동 실행 조건으로 지킨다 |

## 영향과 남은 일

- ADR0014 결정 4의 "현재 AI provider·token·외부 호출은 추가하지 않는다"는 재배치 판단에 한해 이 ADR이 대체한다. 결정 모델 provider·호출 방식·비밀값 관리는 구현 계획에서 정한다. 모델에는 화물 ID·배치·지표만 보낸다. 사용자 정보·주소·토큰은 보내지 않는다.
- 실제 자동 실행은 ROSY D-938(팔 이송 정책 승인, 2026-10-31 플랫폼 로컬 main 착지, 원격 게시 전)의 범위 안에서만 진행된다. 그 범위가 켜지려면 다음이 모두 필요하다.
  - Fleet 사이트 설정의 승인 범위에 Harbor 서비스 principal이 `proposers`로 들어 있다. 참여 팔·상한·만료 시각도 함께 적혀 있다.
  - 기명 운영자가 Fleet에서 범위를 켰다.
  
  D-938은 simulation 팔 이송 HTTP에서만 동작한다. 범위가 꺼져 있거나 만료됐거나 다 쓰였으면 Fleet 승인에서 멈춘다. 이 상태를 자동 실행 완료로 보고하지 않는다. Harbor는 자기 제안을 승인하지 않는다.
- 회전 대응은 OMX 팔 칸별 실물 검증이 필요하다. 검증 전에는 회전 후보가 `ROTATION_NOT_INSTALLED`로 빠진다.
- 무게 제약은 화물 카탈로그 값이 생긴 뒤 넣는다.

## 검증 기준

- 설계32의 수용 시험을 모두 통과한다.
- 결정 모델 응답별 시험을 둔다. 대체 모델(fake)로 다음 응답을 하나씩 넣고 결과를 확인한다.
  - 규칙 위반 제안: 거절
  - 더 나쁜 제안: 계산안 유지
  - 엄격히 더 나은 합법 제안: 채택
  - 같은 점수의 제안: 계산안 유지
  - `veto`: 자동 실행 중지
  - 무응답·형식 오류: 계산 단독으로 판단
  - 4회째 협의 요청: 거절
- 협의 기록이 Plan에 남고, 과거 조회에서 같은 의미로 보인다.
- 허용이 꺼졌거나 만료됐거나 자동 실행 조건을 어긴 경우마다 Command가 0건이다.
- 운영 Fleet·실물 팔 수용은 별도로 기록한다.
