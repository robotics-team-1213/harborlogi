# ADR 0025: 시험 시나리오는 엑셀로 미리 모두 등록하고, 입고는 사람이 결정하며, 재배치는 입고 시나리오 뒤에 보인다

날짜: 2026-11-07

상태: 제안(2026-11-07). 11/05 데일리 회의 결정(입고 명령은 알고리즘, 재배치는 사전 입고 시나리오 뒤)과 11/07 서정민 님 결정(시나리오 이벤트는 사전에 모두 등록, 입고는 먼저 보여 주고 결정 버튼, 재배치 파라미터 입력 제거)을 구현한 것이다. 팀 확정 전이다(KAN-117 · KAN-118 · KAN-119).

- 번호: 병합 시점 `main`의 ADR 번호를 다시 확인한다.
- 잇는 결정: ADR 0010(입고 위치는 계산, 요청마다 계획), ADR 0012(실행은 사용자가 확정), ADR 0017(독립 재배치 R2와 상시 허용 범위), ADR 0024(우선순위 3단계).

## 배경

팀은 시험 시나리오를 엑셀로 만들어 넣고 같은 조건으로 반복 시험하려 한다(KAN-118). 회의는 입고 명령을 알고리즘이 정하고 사용자는 개입하지 않기로 했지만, 이는 ADR 0012와 부딪힌다. 자동 재배치는 상시 허용 범위(k · 최대 이동 · 유효 시간 · 하루 횟수)를 사람이 입력해 켜는 방식이었는데, 회의는 사전 입고 시나리오가 끝난 뒤 재배치하기로 했다.

## 결정

1. **시나리오 이벤트는 미리 모두 등록한다.** 파일 하나에 「초기 배치」(행 · 층, 1×3 컨테이너)와 「이벤트」(종류 · 화물 · 단계 · 제목) 시트를 둔다. 등록하면 화물(1×3), 합성 시작 관측, 모든 입고 · 반출 요청을 한 트랜잭션에서 만든다. 하나라도 틀리면 아무것도 만들지 않고 시트 · 행별로 이유를 보인다. 시간차로 들어오는 이벤트는 다음 단계다.
2. **시나리오 등록은 개발 · 시험 환경에서만 연다.** 합성 관측을 만들기 때문이다. 관리자와 업무 담당 역할이 함께 있어야 한다. 엑셀은 표준 라이브러리로 읽고 크기를 제한한다(새 의존성 없음).
3. **입고 위치는 알고리즘이, 결정은 사람이 한다.** 시나리오의 입고 요청은 이벤트 순서대로 자동 계획(ADR 0010의 예약 방식)을 켠다. 최신 READY 추천에만 ‘이 위치로 결정’을 받고, 결정은 바꿀 수 없는 감사 기록(`plan.decide`)으로 남는다. 요청이 바뀌면 결정은 그 계획에만 남고 새 계획은 다시 결정을 기다린다. 결정은 화물을 움직이지 않는다. 실제 입고 실행 인계는 설치 대응이 생긴 뒤의 일이다. 이로써 회의 결정 「입고는 알고리즘 기반」과 ADR 0012가 함께 지켜진다.
4. **재배치는 입력값 없이 입고 시나리오 뒤에 보인다.** 결정을 기다리는 입고가 있으면 화면은 ‘입고 시나리오 진행 중’만 보인다. 대기로 세는 입고는 결정 화면에 ‘이 위치로 결정’ 버튼이 보이는 것뿐이다. 최신 계획이 READY 추천이고, 계획한 뒤 요청 · 대기열 · 관측이 바뀌지 않았고 관측이 유효 시간 안이어야 한다(workspace.plan_changes). 계획이 없거나 HOLD이거나 기준이 바뀐 입고는 ‘지금 결정할 수 없음’으로 이유와 함께 따로 알리고 대기로 세지 않는다. 그런 요청은 사람의 결정이 아니라 다시 계산하거나 새 관측이 있어야 풀리므로, 재배치를 막으면 풀 방법이 없기 때문이다. 서버도 같은 조건으로만 결정을 받는다. 모두 결정되면 관측 야드에 결정한 입고 위치를 더한 예상 야드로 R2를 미리 계산해 보인다(반출 순서 기준, 저장하지 않음). 실제 재배치 계획은 관측으로만 만든다. 이미 켜진 상시 허용은 끄는 버튼만 남는다.

## 결과

- 시험은 엑셀 한 파일로 같은 조건을 다시 만들 수 있다.
- 사람은 입고마다 위치를 고르지 않고, 알고리즘이 고른 위치를 확인만 한다.
- R2 계산과 실행 조건(ADR 0017)은 바꾸지 않았다. 화면에서 상시 허용을 켜는 입력만 없앴다.

## 남은 결정

- 반출 요청이 남아 있으면 R2는 `OUTBOUND_PENDING`으로 보류한다(ADR 0017). 회의의 「시나리오 뒤 우선순위 재배치」는 반출 대기 중에도 재배치하자는 뜻이라 이 규칙과 부딪힌다. 미리 보기는 반출 순서로 계산해 보이지만, 실제 계획을 만들 때 이 규칙을 바꿀지는 팀 결정이다(KAN-119).
- 입고를 시나리오 묶음으로 계산해 추천 2안을 낼지(KAN-121, 11/07 서정민 님: 추천 개수 2), 지금처럼 요청마다 예약 순서로 계산할지.
- 시간차 이벤트(ETA) 형식. → 입고만 다루는 일정은 ADR 0031(제안)의 「입고 일정」 시트로 정했다. 반출이 섞인 일정은 아직 남았다.
