# ADR 0035: 운영 화면 용어와 사진 기준 야드 2×3 표시

날짜: 2026-11-21

상태: **제안(초안)**. 사용자 확정 표시 규칙을 기록한다. WP01에서 실제 화면·계획 코드는 변경하지 않는다.

대체 제안: [ADR0026](0026-site-map-fixed-container-slots.md) 결정 2의 화면 명명·방향, 결정 3의 자리 이름, 결정 5의 용어 허용 범위. 논리 설치 크기·도달 범위는 보존한다. 결정 1·4·6은 대체하지 않는다.

## 배경

사진 기준으로 실제 야드는 가로 세 열·세로 두 행의 자리로 읽힌다. 기존 계획은 3행×6개 칸에서 `slot_cells=3`으로 행마다 두 자리를 묶는다. 화면 방향을 맞추려고 계획 주소나 팔 도달 범위를 바꾸면 기존 실행 binding과 이력이 어긋난다.

## 결정 제안

1. 현장 고정 자리 화면만 전치한다. 실제 `(r행, s번째 자리, 층)`은 화면 `(s행, r열, 층)`이다. 화면 1행은 위, 1열은 왼쪽이다. 실제 칸 열 c의 자리 번호는 `s = floor((c-1)/slot_cells)+1`이다. 기존 자리 주소·계획 좌표·화물 footprint·`arm_reach`는 그대로 둔다.
2. 위치는 「야드 1행 2열 1층」으로 쓴다. 예를 들어 실제 r2의 첫 자리(칸 c1~c3)는 화면 1행 2열, r3의 둘째 자리(c4~c6)는 화면 2행 3열이다. 평면·3D와 선택 상세가 같은 실제 주소로 왕복해야 한다. 가변 크기·`slot_cells` 없는 다른 현장까지 이 표시를 강제하지 않는다.
3. 임시 판 A·B의 3레인은 각각 왼쪽부터 1·2·3레인으로 가로 나란히 놓는다. 이름은 「임시 판 A 1레인」, 층 상세는 「임시 판 A 1레인 2층」이다. 팔 A·B 모두 야드 전체에 닿고, 임시 판은 자기 쪽만, 반출대는 팔 A 쪽 하나다. 도달 정책과 계획은 바꾸지 않는다.
4. 운영 기본 화면에서는 「관측·원본·인계·대조·회차·#번호·READY/HOLD」를 쓰지 않는다. 필요한 식별자·출처·내부 상태는 **지원용 `<details>` 안에만** 둔다. 기록 화면도 동일하다. 컨테이너 번호·자리·진행 사유는 사람이 읽을 문장으로 쓴다.
5. 기본 작업 상태는 진행 중 / 대기 / 완료다. 예외는 「처리할 것」과 구체적 사유로 분리한다. 끝난 이동 뒤 다음 이동이 아직 시작되지 않았으면 「완료 · 다음 작업 대기 중」이다. 퍼센트·이동 N/M 진행 막대는 없고 「상태는 ROSY 실행 결과로 바뀜」 한 줄을 둔다. 세부 상태·완료 집계는 설계35를 따른다.
6. 상황판 미니 평면은 출발·도착 같은 배경과 갈 자리의 옅은 화물 번호를 쓴다. 화살표·반출 순번 동그라미·「2행×3열×3층」 크기 설명은 넣지 않는다. 출처 없는 인식 차이·장비 상태는 표시 자료를 만들지 않고 연동 전으로 둔다.

## 결과와 검증

표시 좌표와 계획 좌표가 다르므로 전치와 역변환을 함께 시험해야 한다. 기존 이력·저장 주소는 마이그레이션하지 않는다. 야드 6자리×각 층과 임시 판 A·B 각 레인의 이름·선택·2D/3D 주소 일치, 팔별 도달 정책 보존, 운영 기본 화면 금지어와 접힘 안의 지원 정보를 후속 작업에서 검사한다.

[설계35](../design/35-control-dashboard.md)는 화면 대응·상태·연동 전 목록, [설계34](../design/34-role-scenario-access-and-menus.md)는 역할과 메뉴의 목표다. 이 초안으로 기존 ADR의 상태를 수락·대체 완료로 바꾸지 않는다.
