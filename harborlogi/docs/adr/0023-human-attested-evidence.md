# ADR 0023: 기명 현장 확인을 업무 완료 근거의 한 출처로 받는다

날짜: 2026-11-04

상태: 수락(2026-11-04, 사용자 결정 "실운영에서 업무 완료 근거(내려놓기·팔 퇴피)는 자동 근거 생산자가 생길 때까지 기명 현장 운영자 확인으로 받는다. Harbor는 그 기록을 '사람 확인' 출처로 구분해 업무 완료에 쓴다.").
- 번호: ADR 0022는 readiness-gate가 쓴다. 병합 시점 `main`의 번호를 다시 확인한다.
- 연결: 사람 확인 생산자를 켜는 관리자 설정은 ADR 0022의 `EvidenceProducerSetting`(감사 기록이 남는 설정 행)이다. `harbor_web/human_evidence.py:human_evidence_enabled()` 한 곳만 그 행을 읽는다.
- 잇는 결정: ADR 0005 결정 6·7(업무 완료 3요소), ADR 0013(업무 실행 독립), ADR 0019.

## 배경

업무 완료는 Fleet 수행 결과, 내려놓기 근거, 관련 팔 퇴피 근거가 각각 맞아야 선다(ADR 0005). 내려놓기·퇴피를 자동으로 만드는 생산자는 아직 없다. 그동안 운영은 멈춰 있다.

## 결정

1. **사람 확인은 근거 출처의 한 종류다.** 자동 근거와 같은 `MoveEvidence`(내려놓기 + 퇴피)로 장부에 들어가되, 출처 ID가 다르다(`human-attested-placement`, `human-attested-retreat`). 자동 출처 집합과 겹치면 장부 생성이 실패한다. 이 ID는 `/evidence` 수신 경로의 설정 출처가 될 수 없다.
2. **측정값이 아니라 판정이다.** 관절값·구역 점유 해제 같은 측정 필드에 수치를 만들어 넣지 않는다. 장부 도메인을 최소 확장했다.
   - `PlacementEvidence.attested_by`(기본 빈 값 = 자동). 값이 있으면 사람 확인이다.
   - `HumanArmRetreat(arm, attested_by, outside_zone_seen)`: "이 팔이 구역 밖 대기 자세임을 육안으로 보았다"는 판정. 관절값·점유 해제 필드가 없다.
   - 장부는 사람 확인이면 사람 출처 ID와 자체 신선도 창(기본 5분, 자동은 5초)으로만 받고, 내려놓기와 퇴피가 모두 사람 확인이며 같은 확인자일 것을 요구한다. 자동 출처 ID에 사람 판정을 실어도, 반대로 섞어도 거절한다. 장부는 Fleet 상태 문자열을 해석하지 않는다.
3. **누가 확인하는가.** 로그인한 `field` 또는 `operator` 역할(`admin`·`viewer`만으로는 불가). 실행 지시를 제출한 사람과 같아도 된다. 독립 승인은 Fleet ARM 승인이 맡고(ADR 0012·0015), 이 근거는 물리 현장을 본 사람의 사실 진술이어서 소규모 현장에서는 제출자가 현장에 있는 경우가 많다. 누가 확인했는지는 항상 남는다.
4. **무엇을 기록하는가.** 불변 `HumanAttestation`: 확인자(`created_by`), 서버 시각(`created_at`), 대상 Command·단계(`step`/`final`)·`step_index`·mission·attempt·revision, 화물 ID와 내려놓은 위치, 쓴 팔마다 "구역 밖 대기 자세 육안 확인", 메모, 선택적 사진 참조. 화물·위치·팔 목록은 폼이 아니라 장부의 현재 계획에서 서버가 정한다. 팔은 이번 단계에 쓴 팔 전부(최종은 요청 전체)를 모두 확인해야 한다.
5. **결속과 소비.** 제출 시 장부의 현재 단계(WAITING + goal_confirmed, 또는 AWAITING_FINAL_EVIDENCE)의 mission·attempt·step과 일치해야 하고, Command 버전이 낙관적 잠금으로 맞아야 한다. 과거 attempt·다른 Command는 409. 실행기의 근거 콜백(`human_provider`)이 기록을 다시 같은 단계에 대조해 `confirm`/`finish`에 넘기고, 근거 ID(`human-<기록 pk>:placement|retreat`)는 장부가 한 번만 소비한다. 신선도(5분)가 지난 기록은 새 확인이 필요하다. 사람 확인 생산자 설정이 꺼지면 폼도 소비도 멈춘다.
6. **어떻게 보이는가.** 장부 증거 행에 `attested_by`와 사람 출처 ID가 남는다. 운영 현황 실적은 "그중 사람 확인 근거 N건"을 따로 보이고, 업무 타임라인은 "사람 확인" 종류로 확인자·단계·"측정값 아님"을 보인다. 업무 완료 자체는 같은 장부 대조의 결과다.
7. **자동 생산자가 생기면.** 자동 출처를 등록하면 실행기는 자동 근거를 먼저 쓰고(`intake`가 앞선다), 사람 확인은 자동 근거가 없을 때만 쓰인다. 설정을 끄면 사람 확인 경로는 닫힌다. 이미 기록된 `HumanAttestation`과 장부 증거는 이력으로 남고 지우거나 바꾸지 않는다.
8. **경계와 열람 범위(독립 리뷰 반영).**
   - 실행기는 장부 창보다 30초 먼저(`LEDGER_MARGIN`) 기록 제공을 멈춘다. 그래서 경계에서 만료된 확인이 결과 불명 대조로 빠지지 않는다.
   - 확인 제출은 한 번에 하나씩 직렬화한다(SQLite는 행 잠금이 없다).
   - `field`만 가진 사용자는 그 Command가 확인을 기다리고 사람 확인이 켜져 있을 때만 실행 상세를 연다. 제출·취소·대조 같은 다른 동작은 계속 `operator` 전용이다.
   - 설정을 껐다가 신선도 창 안에 다시 켜면, 끄기 전에 받은 기록이 소비될 수 있다. 켜져 있는 동안 기명 확인자가 남긴 기록이므로 받아들인다.

## 결과

- 사람 확인은 센서 진실성을 보증하지 않는다. 확인자의 책임이며, 사진 참조는 선택이다.
- 실행기가 돌고 있어야(`HARBOR_EXECUTOR_ENABLED=1`) 기록이 장부로 넘어간다. 폼 제출이 곧 완료는 아니다.
- 사진 파일 업로드는 이 결정에 없다. 참조 문자열만 받는다.
