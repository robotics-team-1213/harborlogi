# ADR 0028: Harbor 업무·관제 단위·장치 owner·공통 서비스·호스트의 책임을 구분한다

날짜: 2026-11-08

상태: 수락(사용자 요청: ADR과 GitHub에 Harbor 및 기타 구성의 책임을 기록하고 갱신). 기존 책임 결정을 현재 안내에 모으는 문서 변경이다. API·권한·계정 구현·배포·실물 수용을 변경하지 않는다.

## 배경

통합관제 R의 목표 호스트로 N100·16GB Ubuntu 컴퓨터를 정했다. 물리 호스트를 통합관제·팔 owner·공통 Account와 같은 것으로 읽으면, Harbor의 업무 확정을 장치 실행 승인으로 오해하거나 R을 옮길 때 셀·장치의 원장까지 옮기게 된다.

ADR0005·0013·0015·0018·0021은 업무·실행·신원·관제 진입·배치 경계를 이미 정했다. 이번 결정은 그 관계를 설명하는 정본을 하나 두고 구현·배포·실물 근거를 구별한다. 과거 ADR·검증 기록의 당시 본문은 보존한다.

## 결정

1. **Harbor의 정본은 항만 업무다.** 화물·업무 위치·지시·계획 버전·업무 장부·다음 단계 판단·완료 조건을 소유한다. 플랫폼의 admission·장치 자원 점유·관절 계획·최종 명령·안전 원장을 복제하지 않는다. 물리 실행 결과 하나가 반출 업무 전체 완료를 뜻하지 않는다.
2. **Harbor는 R 하나의 공개 Fleet HTTP 계약으로 연결한다.** R은 직접 소유 장치와 하위 셀을 구별한다. 팔 제안은 R을 통해 소유 셀에 전달되고 실물 ARM admission은 셀의 기명 운영자·현재 부모 증명·기존 자원/안전 검사를 거친다. Harbor 사용자 확정, 주행 위임 승인, 셀 ARM admit, 장치 owner의 최종 수락은 다르다. Harbor에 자동 승인·직접 셀 연결·ROS/플랫폼 DB 접근을 추가하지 않는다.
3. **책임표의 정본은 [Harbor와 ROSY의 책임](../responsibilities.md)이다.** R·셀·CORE·OMX·World·Decision·Account·Monitoring·Media·Learning·제품 앱·물리 호스트를 여기서 구별하고, README·PRODUCT·CONTEXT·플랫폼 소비 기준은 이 문서에 연결한다. HTTP 경로·schema·허용 범위는 기존 [플랫폼 소비 기준](../platform-contract.md)을 따르며 이 문서로 바꾸지 않는다.
4. **사람 공통 로그인과 기계 서비스 신원을 분리한다.** 사람 신원은 공통 Account로 연동하는 원칙을 따르고 Harbor는 자기 업무 역할과 감사를 유지한다. R이 Harbor 서버를 인증하는 전용 service principal/토큰, 독립 관측 자격, 셀 기명 승인은 사람 로그인과 합치지 않는다. 공통 로그인 때문에 DB·비밀번호·operator 토큰을 공유하지 않는다. 문서의 목표를 로그인 연동 완료로 기록하지 않는다.
5. **호스트는 실행 위치이며 권한 주체가 아니다.** N100은 R의 목표 호스트다. Harbor 동거 방향과 모델 PC 임시 배치는 ADR0021의 2026-11-06 개정을 따르며, 이번 결정으로 서버를 옮기지 않는다. 동거하더라도 Harbor의 Compose project·DB·TLS·서비스 자격과 ROSY의 자원을 구별한다. 서비스 구성·영상 비용·백업/복구·동시 부하를 확인하기 전 N100 처리 용량을 보장하지 않는다.
6. **구현과 수용을 따로 기록한다.** R→셀 ARM 제안·조회·근거 중계의 소프트웨어 근거는 기존 ADR0018과 검증 기록을 따른다. ARM physical-evidence·recheck 중계의 직계 자식 제한과 주행/ARM 승인 분리를 설명하되, 일반 3수준 관제 topology를 모든 ARM 경로의 지원 완료로 확대하지 않는다. 이번 문서 변경으로 플랫폼 소비 pin을 올리거나 실제 호스트 연결·장치 동작·N100 이전을 완료 처리하지 않는다.

## 기존 결정과의 관계

| 결정 | 관계 |
|---|---|
| ADR0005·0013 | Harbor 업무 계획·장부·완료 판정과 ROSY 공통 실행·안전의 분리를 유지한다 |
| ADR0015 | Harbor 사람, 서비스, 셀 승인, 독립 관측 신원을 구별한다 |
| ADR0018 | 외부 앱의 R 단일 입구와 셀의 승인 책임을 유지한다 |
| ADR0021 | 같은 호스트의 자원 격리와 2026-11-06 임시 배치·CI 이미지 갱신 결정을 유지한다 |
| ROSY D-893·D-960·D-965·D-974 | 논리 관제·프로그램·장치 owner·물리 호스트와 화면의 층을 구별한다 |

## 결과와 검증

독자는 업무와 장치 실행의 주인, 관제 계층, 공통 서비스, 물리 배치를 따로 확인할 수 있다. 대신 저장소가 다른 책임은 각 정본 링크를 유지해야 한다. 코드가 없는 새 API나 안전·장치 지원을 문서로 약속하지 않는다.

기존 Harbor unittest와 문서 링크·경계 검토를 수행하고 결과를 PR에 남긴다. 실제 Fleet 통합·브라우저·운영 배포·실물 동작을 새로 검증한 것으로 세지 않는다. ADR 번호는 병합 직전 최신 팀 main과 다시 대조한다.
