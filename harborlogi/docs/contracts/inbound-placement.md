# RFID 입고와 실제 장치 위치

Harbor는 화물의 입고 회차, 반출 일정, 배치 계획과 업무 장부를 관리한다. ROSY는 태그 판독, 현장 실행 가능 여부, 팔 작업과 위치 관측을 관리한다. 양쪽에서 같은 화물을 대조할 때는 화물 코드와 정본 슬롯 주소를 사용한다. `C-1`은 화물이고 `yard-r1-c4-l1`은 자리다. 원본 EPC나 화면 칸 이름으로 자리를 지정하지 않는다.

## 기존 연동

아래 입고 판독 흐름은 공급 작업 바인딩과 EPC 매핑이 구성된 Cell Fleet에서 검증했다. 합성 매핑 시험은 ASCII 화물 코드와 뒤쪽 NUL 패딩을 담은 C-1부터 C-21까지의 태그를 사용한다. 현장에서는 기존 태그를 한 개씩 읽어 인코딩과 화물 코드를 확인하고 전체 EPC를 보존한다. 읽은 순서는 화물 번호를 정하지 않는다. 등록 판독은 입고 사건을 만들지 않는다.

| 시점 | 주체와 기록 |
|---|---|
| 입고 판독 | 셀 PC가 선택한 EPC를 Cell Fleet에 전달한다. Cell Fleet은 현장 매핑과 공급 작업 상태를 검사한다. Harbor는 Fleet R을 통해 받은 `container.received_at_intake`를 도착한 화물의 입고 장부에 한 번 반영한다. 이 시점에는 야드 위치가 없다. |
| 자리 선정 | Harbor는 지정 목적지가 있는 계획을 우선한다. 지정이 없을 때는 같은 관측과 반출 순서로 같은 결과가 나오도록 적법한 후보를 평가한다. 선출고 화물을 막는지, 지지·도달 조건, 기존 예약을 고려한다. 후보가 없으면 보류한다. |
| 실행 제안 | 입고 추천에서 만든 `harbor_plan` 단계에는 `cargo_id`, `src_site=belt`, `dst_site`가 들어간다. Harbor는 제출 전 `request_key`와 본문을 기록한다. 응답 유실 시 같은 키를 조회한다. ROSY는 실행 조건을 검증하고 실제 승인·실행을 담당한다. |
| 적재 반영 | Harbor는 적용된 `container.stored`의 `object_ref`, `slot_ref`, `event_id`, `observation_ref`로 야드 관측을 만든다. 등록 화물·크기·슬롯·공간 검증에 실패하면 반영 거절을 기록한다. 명령의 목적지와 별개로 카메라의 `site_ref`, `object_ref_read`, 관측 시각과 보정 버전을 대조할 수 있다. |

## 일정 변경과 대체 배치

- ROSY에 보내기 전에는 자동 재계획 대상의 일정이 바뀌면 새 Plan에 추천과 예약을 기록한다. 이미 제출한 요청은 당시 목적지와 요청 키를 보존한다. 타임아웃은 접수 여부 불명 상태다.
- 진행 중인 작업의 목적지를 변경하려면 기존 요청을 대조하고, 취소 대상 단계와 이미 실행된 단계를 확인한 뒤 새 관측으로 계획한다. 취소 응답 하나로 작업 중인 칸을 비우지 않는다.
- 지정 칸을 쓸 수 없으면 ROSY가 거부 사유를 반환한다. 대안은 Harbor가 다른 예약과 충돌하는지 확인하고 새 목적지를 제출한다. ROSY가 임의로 다른 칸에 둔 뒤 원래 목적지를 완료 처리하면 안 된다.
- 예를 들어 C-1의 추천이 일정 변경으로 c1에서 c4로 바뀌면, 제출 전에는 c4를 새로 예약할 수 있다. c1로 이미 제출했다면 그 작업을 대조할 때까지 c1을 보호한다. 실물 관측이 c4를 가리키면 두 위치의 차이를 기록하고 재확인한다.

## 입고 회차와 배치 결과 교환

Harbor는 `container.received_at_intake`에 `intake_occurrence_id`가 있으면 회차와 수령 이벤트를 보존한다. 등록 화물에 미실행 입고 주문이 하나면 그 주문을 연결하고, 없으면 화주 등급 끝에 주문을 생성한다. 후보가 여럿이거나 이전 작업이 실행 중이면 대조를 기다린다. 미등록 화물, 야드 관측 부재, 자동 계획 수 제한은 다음 수신 주기에 다시 확인한다. 같은 화물의 다음 입고는 새 회차와 주문으로 관리한다.

Harbor가 화물 코드의 화주명·화주 등급·중량·부피·도착지와 주문의 항차·마감·순서를 보관한다. 등록 태그는 하나의 화물에 연결된다. 반복 입고는 같은 화물을 참조하는 별도 주문을 만들 수 있으며 기존 태그와 화주 배정은 유지된다. 입고 RFID와 놓기 결과로 화주를 배정하지 않는다. ROSY에는 작업에 필요한 화물 코드, 회차, 시도와 장소를 전달한다.

운영 Fleet에서는 공급 완료 근거가 R의 셀 작업 원장에 있고, 셀 PC의 RFID 판독은 Cell Fleet에 쌓인다. 판독과 공급 완료를 같은 입고 회차에 결속하는 경로는 ROSY #864(2026-11-26 병합)에 있고, 같은 날 두 현장 Fleet에 운영 리더 설정으로 전환했다([ROSY Ops `docs/rfd40-intake.md`](https://github.com/robotics-team-1213/rosy-ops/blob/main/docs/rfd40-intake.md)). 샘플 주소나 화물 이름만 일치한다고 완료를 생성하지 않는다. 공급 계획 생성용 시뮬레이션 프로필을 운영에서 켜지 않는다. 실물 판독 한 건이 Harbor 입고 기록까지 이어지는 운영 수용은 아직 확인하지 않았다.

| 기록 (ROSY #864) | 작성 주체 | 수신자가 확인할 내용 |
|---|---|---|
| 입고 회차와 공급 바인딩 | 공급 작업을 만드는 Fleet R | 새 회차에 `intake_occurrence_id`를 한 번 부여하고 `object_ref`, 공급 셀, 이송 ID, 공급 작업 ID를 함께 저장한다. 같은 작업 재시도에는 같은 회차를 쓴다. |
| 비공개 판독 후보 | 셀 PC의 인증된 판독을 받은 Cell Fleet | `source_workcell`, 순번, `observation_ref`, 관측 시각, 매핑 버전, 판독 상태와 매핑된 화물 코드를 보존한다. 원본 EPC는 셀 내부에 둔다. 직접 상위 Fleet만 후보를 읽는다. |
| 검증된 입고 사건 | Fleet R | 같은 셀의 공급 완료 시각과 화물·회차를 대조한다. 후보와 회차가 유일할 때 수령 기록을 한 번만 만든다. 공급 근거가 늦으면 재시작 후에도 대기하고, 후보가 여럿이면 보류한다. Harbor에는 확정된 입고 사건만 전달한다. |

스케줄 화면의 모의 배치는 미래 예측이다. 현재 재고는 마지막 야드 관측, 이미 인계한 목적지는 해당 요청의 전송 본문에서 확인한다.

Harbor는 회차에 연결된 `harbor_plan` 요청의 최상위에 `intake_occurrence_id`와 `placement_attempt_id`를 넣는다. 배치 시도 값은 제출 당시의 `request_key`와 같다. ROSY는 실제 화물과 슬롯을 확인한 `container.stored`에 두 값과 `object_ref`, 관측된 `slot_ref`를 반환한다. Harbor는 회차, 화물, 최신 실행 시도와 관측 시각을 대조한다. 다른 칸이 관측되면 공간 검증 후 실제 위치를 표시하고 요청과의 차이를 남긴다. 관측 충돌은 원본 사건을 보존하고 재처리한다. 이미 더 최신인 야드 관측은 되감지 않는다. `/inventory/`의 최근 입고 회차 표에서 요청한 자리와 관측한 자리를 확인할 수 있다.

회차 필드가 없는 기존 이벤트는 기존 화물별 장부 규칙을 따른다. 회차에 연결된 화물의 적재 결과로 인정하려면 두 식별자가 필요하다. 현장 배포의 수용 여부는 Fleet 양단, RFD40 판독, 실제 셀 인식 결과로 확인한다.

Harbor 지시 위치는 저장된 계획에서 읽는다. ROSY에 보낼 수 없는 동안에도 지시 위치와 Harbor 사전 점검 사유가 보인다. 전송 시 `propose=true`를 명시한다. ROSY의 `PROPOSED`는 제안 접수를 뜻하며 실제 팔 동작과 보정 상태는 후속 단계에서 검증한다. `SITE_NOT_CALIBRATED`와 `STAND_NOT_CALIBRATED`는 현장 보정 필요, `SITE_ARM_NOT_ALLOWED`는 현재 장치 구성에서 실행 불가로 표시한다. 요청 위치, 실제 제출 위치, 확인된 적재 위치는 별도 열에 남는다. ROSY의 작업 중단만으로 적재 위치를 채우지 않는다.

화물에 별도 시각 표식을 붙이지 않는 설비에서는 ROSY가 입고 RFID로 확인한 화물, 같은 회차의 이송 작업, 독립적으로 검증한 놓기 위치를 결합해 `identity=attested`로 보낸다. Harbor는 이 경로를 **RFID 작업 추적 · 놓기 위치 검증**으로 표시한다. 화물 ID와 위치를 직접 관측한 `identity=observed` 결과는 **화물과 위치 직접 관측**으로 표시한다. 요청한 자리만으로는 두 경로 모두 성립하지 않는다.

기존 차량 입고 장부에는 화물별 최신 회차를 표시한다. 새 회차가 확인되면 앞 회차의 적재 위치를 비우고, 해당 회차의 놓기 결과를 받으면 현재 위치를 기록한다. Harbor의 차량 장부 시계와 Fleet의 RFID 시계에는 시차가 있을 수 있어 두 시각의 선후로 회차를 고르지 않는다. 수신 원장은 사건을 보존하며 Harbor는 마지막 처리 순번과 보류 사건을 별도로 저장한다. 다음 주기에는 새 사건과 대조가 남은 사건을 읽는다.

새 규칙의 수용 시험은 같은 C-1의 두 번째 입고, 첫 회차의 지연 이벤트, 같은 이벤트 재전송, 제안 후 일정 변경, ROSY가 다른 칸을 보고한 경우를 포함한다. 회차가 불명확한 증거는 최신 예약을 완료하거나 해제하지 않는다. 빈 칸과 판독 불가도 구분한다.

로컬 교차 시험은 `harborlogi/`에서 `python -m tools.integration.rfid_placement --platform-root <rosy-platform 체크아웃> --platform-sha <커밋 SHA>`로 실행한다. 합성 판독으로 수령부터 실제 양측 애플리케이션의 배치 요청·관측 반환과 야드 화면까지 대조한다. 야드 일부만 본 관측은 배치 계획의 근거로 사용하지 않는다. 늦게 도착한 자료는 관측 시각 순으로 대조한다.

기존 API와 계획 규칙은 [플랫폼 계약](../platform-contract.md), [자동 배치 결정](../adr/0010-automatic-placement-and-replanning.md), [자리별 인식 계약](rosy-cell-site-recognition.md)에 있다.
